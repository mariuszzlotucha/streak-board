## Research Question

The change folder holds no request, frame or plan (`context/changes/grid-state-feedback/change.md`, status `new`), so the question comes from the roadmap. S-21's outcome: "odznaczone, zaległe i bieżący okres są rozróżnialne bez legendy, a po odznaczeniu pojawia się krótkie potwierdzenie" (`context/foundation/roadmap.md:89`), anchor MS-02: "stan siatki jest widoczny od razu: odznaczone, zaległe i bieżący okres są rozróżnialne bez legendy, a po kliknięciu użytkownik dostaje potwierdzenie zapisu" (`:30`). Its one unknown: "Jak oznaczyć zaległość bez mylenia z odznaczeniem (kolor z tokenów, kształt, tekst)? Owner: user. Block: no — rozstrzyga `/10x-frame`" (`:96`); its risk: "nowe kolory muszą przejść `node scripts/token-contrast.mjs` w obu motywach; potwierdzenie nie może zasłaniać siatki" (`:97`). Prerequisite S-20 is done (`:48`, archived as `context/archive/2026-10-19-grid-mobile-readability/`).

So: (1) what the grid shows today for each cell state and for the current period, (2) what feedback a tick gives today and which signals exist to hang a confirmation on, (3) which prior decisions, tokens, lint rules, smoke/e2e bindings and visual gates bound the change, (4) which files S-21 shares with S-22 (`grid-save-reliability`).

## Summary

In the S-20 phone screenshot (`context/archive/2026-10-19-grid-mobile-readability/screenshots/phase-1-states-owner-mobile.png`, 375 px) done is a filled green square with a check, missed a pale pink square with a red X, open a grey square with a dash, and not-joined a blank grey square: open and not-joined differ by a 16 px dash only.
- **Nothing marks the current period.** `CheckoffGrid.astro:16` computes `current = grid.periods.length - 1` and uses it only to choose the live island (`:67-68`); the period `<th>` (`:36-43`) carries no class, text or `aria-current` for it, and the row header's `font-medium` (`:56`) marks the viewer, not the period. The current column is recognisable only as the rightmost one and, for a participant who has not ticked, by the dash. A weekly grid's current cell is `open` for the whole week, including a Sunday afternoon (`grid-rules.ts:54-62`; fixture `NOW` is a Sunday, `dashboard-fixtures.ts:211`).
- **The only feedback after a tick is the optimistic flip, and nothing marks the save.** `CheckoffControl.tsx:68-75` flips the row to the `text-success` "Done today" line with `CircleCheck` and Undo (`:112-128`), publishes `publishChecked` so the viewer's grid cell turns green (`ViewerGridCell.tsx:16-18`) and `publishDelta` for the Leaderboard. ## Detailed Findings

### The grid and its cells today

- Rules: `CellState = "done" | "missed" | "open" | "notJoined"` (`src/lib/grid-rules.ts:14`); `done` when a stored key normalises to the period, `open` for the current period without one, `notJoined` for a closed period before the join period, `missed` otherwise (`:48-63`); `once` tasks have one cell, `done` or `open` (`:91-93`). Columns run oldest-left, current-right (`:84-85`, `:26`). FR-013 fixes these four states and the horizon 7/4/1 (`context/foundation/prd.md:123`); a fifth state or a different horizon is a PRD change.
- Markup: `src/components/tasks/GridCell.tsx:24-31`: `span.mx-auto.flex.size-7.items-center.justify-center.rounded-md` + state classes, a `size-4` lucide icon (`aria-hidden`), then `<span className="sr-only">{cellLabel(prefix, state)}</span>`. Labels: `CELL_STATE_LABELS` = done / missed / open / "not joined" (`src/lib/grid-labels.ts:35-40`), e.g. "Kasia, Mon 13 Oct: done" (`:48-50`). Comment `:6`: "Only pairs `scripts/token-contrast.mjs` checks."
- Live cell: `ViewerGridCell.tsx:15-19` reads `useCheckedTasks().get(taskId)` and renders `GridCell` with `done`/`open`, or `initialState` while the store is empty (server and first client render). Only the viewer's current cell is an island (`CheckoffGrid.astro:67-71`).
- Grid headers: `<th scope="col" class="px-0.5 font-normal text-muted-foreground w-7|w-12">` with `periodHeader` lines as `span.block.whitespace-nowrap` (`CheckoffGrid.astro:36-43`; `grid-labels.ts:22-26`: `["Mo", "5"]`, `["14 Sep"]`, `["Done"]`). No "today"/"this week" word anywhere in the header text; the screen-reader period name is "Mon 13 Oct" / "week from 13 Oct" (`:29-33`), also without a today marker.
- What the phone screenshot shows (`phase-1-states-owner-mobile.png`, `owner` at 375 px, fixture Sunday 11 Oct): for "Water the plants" Olivia's row is X X X ✓ ✓ ✓ ✓ and Max's X X X X ✓ ✓ –; for "Read 20 pages" Sam's row is four blank grey cells, X X ✓. ### Feedback after a tick today

- Optimistic path, `src/components/tasks/CheckoffControl.tsx:64-105`: `setChecked(next)` (`:71`), `publishChecked(taskId, next)` (`:72`), `setPending(true)` (`:73`), `publishDelta(viewerId, delta)` (`:75`), then `await sendCheckoff(...)` (`:77-81`). `saved` → `setPending(false); return;` (`:83-86`). `stale` → reload (`:87-91`). Otherwise rollback (`:93-97`), `expired` → reload (`:98-101`), `rejected`/`failed` → `setPending(false)` and a `role="alert"` message (`:103-104`, `:152-156`; texts `:15-18`). Focus moves to the replacing button once (`:57-62`).
- Visible states: unticked = "Mark done" (primary button, `:132-144`); ticked = `text-success` line with `CircleCheck` and `DONE_LABELS` "Done" / "Done today" / "Done this week" (`:9-13`, `:112-115`) + outline "Undo" (`:116-129`); pending = `aria-disabled` with `opacity-50` and no pointer events (`:22`); streak number in its own span (`:146-151`).
- Signals available for a confirmation: inside the control, `result.kind === "saved"` (`:83`); outside it, nothing: `checkoff-sync.ts` holds `Map<taskId, boolean>` (`:39-58`) and `Map<userId, delta>` (`:8-29`), replaced on each publish, no event log, no saved flag. `useCheckedTasks` is `useSyncExternalStore` over it (`src/components/hooks/useCheckedTasks.ts:8-10`). Subscribers: `ViewerGridCell.tsx:16` and `Leaderboard.tsx:18` (worker grep).
- PRD: the guardrail "Odznaczenie tasku musi być natychmiastowe (bez zauważalnego opóźnienia)" (`prd.md:40`), US-01 "wynik jest natychmiast widoczny" (`:48`), FR-013 "Komórka widza w bieżącym okresie zmienia się od razu po odznaczeniu" (`:123`). ## Architecture Insights

- The cell is one pure component rendered on the server and in the island with identical markup, so a state look changes in one place (`GridCell.tsx`), and nothing but the sr-only label text and its position is bound by tests: colours, icons, rings and borders are free within the token and lint rules.
- Column-level state (the current period) has no home today: `CheckoffGrid.astro` knows `current` but passes cells only `state` and `labelPrefix`. A header mark (`aria-current="date"` on the `<th>`, a class on the `<td>`) stays in S-20's file; a per-cell "current" look would add a prop to `GridCell`.
- The save result is private to `CheckoffControl`; the cross-island store is net state, not events. Anything that must react to "saved" outside the control (a cell flash, a Leaderboard cue) needs a new store value or a timestamp, which also touches `tests/unit/checkoff-sync.test.ts:74-112`.
- The repo's accessible, smoke-safe confirmation shape is an empty `role="status"` element that gains short text after the action and clears on a timer (`CopyInviteLink`); a toast is both decided against for ticks and the shape that covers the grid on a phone.
- Light theme is the only theme that exists at runtime and the only one gated; "both themes" is a document check against the `.dark` block.

## Open Questions

For `/10x-frame` (the roadmap routes the unknown there) and then `/10x-plan`; the first two are product decisions for the owner.

1. **What "zaległe" means.** The grid has no "overdue" state: `missed` is a closed period without a check-off (red X today), `open` is the current period without one (grey dash today). Does the owner mean missed days (already red) or the still-undone current period (grey, and for a weekly task grey all week)? The answer decides whether the work is on `missed` vs `done` (both already strong), on `open` vs `notJoined` (the weak pair), or on the current column.
2. **What "potwierdzenie zapisu" is allowed to be.** The notifications decision excludes a toast per tick; the e2e and smoke exclude a second exact "Done today"; the only server-confirmed signal is inside `CheckoffControl`. Options the constraints leave: (a) treat the existing flip (green line, cell, streak) as the confirmation and make the pending→saved transition visible (today 50 % → 100 % opacity on Undo); (b) a `CopyInviteLink`-style empty `role="status"` line in the row that reads e.g. "Saved" for ~2 s after `saved`; (c) a brief highlight of the cell on `saved` (new store value, `motion-reduce` handling, no precedent). (d) a toast would need the owner to overturn the 2026-10-17 decision and a client-side toast that does not exist.
3. **Marking the current period.** `aria-current="date"` on the `<th>` plus a visible mark (header in `text-foreground font-medium`, a ring/inset-ring or `border-b-2` on the column) stays in `CheckoffGrid.astro` and passes lint; whether the mark goes on the header, the column or the cell, and whether a weekly "current" also needs a word, is a design choice. Non-text marks need a 3:1 pair in `token-contrast.mjs` if they use a tinted colour.
4. **Open vs not-joined.** A dashed border, a hollow circle, or a lighter tint on `notJoined` separates them without a new token; a tint on `open` (`bg-success/10`, `bg-primary/10`, `bg-warning/10`) needs its icon colour re-gated (`success on success/10` is already 4.66, `warning/10` is unlisted).
5. **Ordering with S-22.** (b) and (c) write `CheckoffControl.tsx`; S-22 will write the same handler and may change optimistic to server-wait. Either S-21 goes first and S-22 rebases, or the confirmation is framed together with S-22; parallel worktrees on the two slices are not independent (lessons: "Run independent slices in parallel git worktrees").
6. **Gating a transient confirmation.** No fixture can pin a saved or transient state; `ui-screenshots.mjs` would need a control that releases the held request and waits for the status text, or `CheckoffControl` a `fixed*` prop like `RemindersToggle`.
7. **The e2e "1" collision** (Summary, last bullet): verify by running the round-trip spec with a faked date in the first week of a month (or on 2026-11-01); if confirmed, fix the locator (e.g. scope the streak assertion to the streak element) in whichever slice touches the spec first.
8. **Device rows.** Phase 28's rows 1.8, 1.9, 2.2–2.4 are open; S-21 changes what those rows look at, so the plan should say whether S-21's manual rows replace them.
