## Architecture Insights

- The deployed artifact is Vite's bundle of `src/` imports; `dependencies` versus `devDependencies` changes GitHub's alert scope and `npm audit --omit=dev`, not `dist/`. The one advisory in the bundle (`devalue`) is fixed by a patch release of a transitive dependency.
- Cloudflare's toolchain is one chain: `@astrojs/cloudflare` → `@cloudflare/vite-plugin` → `wrangler`/`miniflare`/`workerd`, with exact pins inside the plugin and inside miniflare. Fixes for `undici` and `sharp` therefore arrive through the plugin, not through the root's own `wrangler` range, and the preview used by smoke and e2e (`astro preview` on the Cloudflare runtime) is where a plugin bump would show.
- Two Node-version mechanisms exist in npm: `engines` + `engine-strict` applies every package's claim to the installing machine; `devEngines` applies the project's claim only. The lockfile already contains packages whose claims exceed `.nvmrc`, so the first mechanism cannot be switched on without moving `.nvmrc` first.
- The `ai-review` gate is the one place that installs on `.nvmrc`'s exact version and the one required check that a Dependabot-triggered run cannot satisfy with a model call; both facts follow from `review.yml` and the action, not from the app.
