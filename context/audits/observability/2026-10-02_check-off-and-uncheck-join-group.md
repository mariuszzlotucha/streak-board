# Observability audit — check-off and uncheck, join group (2026-10-02)

Evidence tags used below: **[R]** observed in the runtime probes (production build on local workerd, fake Supabase, 97 probes); **[R-emu]** observed but emulates a Supabase behaviour that production may not exhibit; **[S]** static, verified by reading the cited source (app or dependency); **[I]** inference.

IDs: findings are **G#** (cross-cutting, both flows), **A#** (check-off and uncheck) and **B#** (join group); runtime probes keep the harness names **C#**, **J#** and **P#** (for example `C1a`, `J5`, `P13b`); assumptions are **AS#**.

## 1. TL;DR

- **Supabase clients return failures; the app only reports throws.** postgrest-js and auth-js hand back `{ error }` instead of throwing, while every route's `try/catch → console.error` waits for an exception. Of the 26 Supabase call sites in `src/`, 15 leave no log line for any failure (2 never read `error`, 13 read it, map `error.code` to a redirect and drop it). Proven at runtime for the join RPC (J1, J2, J5); the 12 other branches are read from source.
- **The auth middleware treats every failure as "signed out".** `src/middleware.ts:11-14` discards the `getUser()` error, so an Auth outage, a rejected key or a missing secret becomes a silent 302 to `/auth/signin`, byte-identical to a real sign-out (C1a–C2e vs control C1f). The check-off island reads that 302 as `expired` and reloads the page.
- **Everything is flattened into a 302 or 200 plus an enum, and the log lines carry no identity.** `42501` (RLS denial, revoked grant, anon downgrade) becomes "forbidden" with no log; status codes cannot separate failure from success; the 24 log sites print `(constant label, raw value)` with no user, task, group, route or HTTP status.
- **Outside the handlers only framework defaults exist:** Astro logs one stack string and returns an empty 500, stream errors after the first chunk are not logged, and the browser side has no capture at all.
- **Most important consequence:** a Supabase Auth outage, a wrong `SUPABASE_KEY`, or a `join_group` function missing after a deploy/migration skew shows users "signed out" or "Something went wrong", while Workers Logs holds ordinary 302s and **zero application log lines**. The CI post-deploy check is anonymous and cannot see any of it.
- **Proof status:** the two critical findings and most mediums were reproduced on a local production build; client-side behaviour and Workers Logs storage were not observable (Section 8).

## 2. Capture model

How a failure travels from code to a human here (all **in repo** unless marked):

- **Runtime:** Cloudflare Workers running Astro 7.3.2 SSR through `@astrojs/cloudflare` 14.3.1 (`astro.config.mjs:11,16`, `wrangler.jsonc:4`). The Worker entry is `export default { fetch: handle }` with no try/catch (`node_modules/@astrojs/cloudflare/dist/entrypoints/server.js:2-4`, `dist/utils/handler.js:36-88`). Browser side: React 19 islands. Only external dependency: Supabase (PostgREST and GoTrue).
- **Tracker:** none. No Sentry/OTel/Datadog/etc. in `package.json`, `src/` or config (repo-wide grep, twice). No `waitUntil`/`cfContext` use, no release or version tag, no sampling or scrubbing hooks.
- **Logging:** 24 `console.error("<constant label>", <raw value>)` calls in 17 files, no other console method in `src/` (`eslint.config.js:25` warns on `no-console`, each site carries a disable comment). Output goes to Cloudflare Workers Logs (`wrangler.jsonc:12-14`).
- **Boundaries:**
  1. Route level: 15 of 16 API handlers wrap their body in `try/catch → console.error → 302 /dashboard?error=<code>`; check-off and uncheck return a typed outcome mapped to JSON or a redirect (`src/lib/checkoff-response.ts:9-34`). `src/pages/api/auth/signout.ts` has no try/catch.
  2. Astro: exceptions escaping middleware, endpoints or pages are caught, logged as one `console.error` string (`err.stack`) and answered with an empty 500 (`node_modules/astro/dist/core/routing/handler.js:59-108`, `core/errors/default-handler.js:105`); there is no `src/pages/500.astro`.   3. Middleware: runs first on every request, no try/catch, discards the `error` of `getUser()` (`src/middleware.ts:7-32`). Astro's own Origin check runs before it and answers a text 403 without logging (`node_modules/astro/dist/core/middleware/load.js:12-15`, `core/app/origin-check.js:23-27`).
  4. ## 4. Systemic root causes

1. **Libraries return failures, and the app reports only throws.** The per-route `try/catch → console.error` (e.g. `src/pages/api/groups/join.ts:39-44`) is unreachable for backend failures because `{ error }` comes back as a value (`postgrest-js/dist/index.cjs:418-455`, `auth-js/dist/module/GoTrueClient.js:2713-2723`); the code comments assume the opposite (`join.ts:40`). `middleware.ts:11-14` and `signout.ts:8` never read the error; 13 more branches read it and drop it (list under G2). The local reasonable decision was one try/catch pattern copied per route. Explains G1, G2, G9, part of G3 and G12.
2. **Auth state is decided by a middleware that maps every failure to "signed out".** `getUser()` returns `{ user: null, error }` for both a missing session and a service failure, and `src/middleware.ts:11-20` does not look at which; a null client (missing secrets) takes the same path (`:15-17`). The blast radius is every protected route. Explains G1, G13 and gives G11 its symptom.
3. **One flattening vocabulary.** Every non-check-off outcome is a 302 with `?error=<code>` (documented contract, `README.md:182`) or a 200 with a banner (`dashboard.astro:124-139`, no `Astro.response.status` anywhere in `src/`); the mappers key on SQLSTATE or `code` only, default to `unknown`, and never read `status` (`group-errors.ts:14-27`, `task-errors.ts:11-15`, `auth-errors.ts:15-25,51-68`). The closed code set exists so `?error=` is never reflected (`dashboard.astro:34-35`), a sound choice that also drops the cause. Explains G3, G5, A2, B3, B5.
4. **Log lines carry no identity and sometimes no stack.** 24 `console.error(label, raw)` sites; PostgREST errors are plain objects (no stack) rethrown 8 times (`groups.ts:22,29,37`, `tasks.ts:20,36,63,73`, `checkoffs.ts:15`); 5 `new Error` without `cause`, none with; no user, task, group, route or status; labels shared across several reads (`dashboard.astro:126`, `checkoff.ts:42`). Explains G8, G6 and weakens every logged finding.
5. **Outside the handlers only framework defaults and nothing client-side.** Astro's catch logs one string and returns an empty 500, drops `cause`, does not see stream errors, and Origin-check 403s are silent; the browser has no capture and the island's `catch {}` collapses every failure to `failed`. Explains G4, G6, G7, G14.
6. **Release verification and identity by anonymous status probes.** The release job checks three unauthenticated URLs and nothing names the build (`ci.yml:121-150`, `wrangler.jsonc:3`). Explains G10, G16 and why G1 would ship unnoticed.

## 6. Recommended fix order

Ordered by blindness removed per unit of effort. Constraints that any implementation must respect: log ids or hashes, never e-mail addresses; the invite code is a bearer secret, log length or a short prefix only; do not change the check-off response contract unless a finding needs it (37 `toEqual` assertions on the `ok` and `forbidden` outcome shapes in `tests/integration/task-checkoff-flow.test.ts`, 4 smoke steps on the exact 200 body, the island's status mapping in `checkoff-client.ts:52-62`); adding fields to `unknown` is free; a new server-rendered `role="alert"` breaks the `NO_ERROR_ALERT` smoke steps; avoid double reporting once a tracker exists (the Astro catch, the route catch and the helper can all see one failure).

1. **A shared `reportError` / `logError` helper, first used by the middleware fix (G1).** Closes G1 and the foundation of G8. The middleware must stay quiet for `AuthSessionMissingError` (every anonymous page view returns it) and decide the response for a real service failure: the island already maps a 5xx to `failed`, and smoke's anonymous steps (302 for a missing session) must still hold. Add a test that forces `getUser` to return a service error and asserts both the response and the log call (existing precedent: `tests/integration/auth-callback.test.ts` mocks `@/lib/supabase`; a middleware test also needs `astro:middleware` handled).
2. **Apply the helper to the 13 `if (error)` branches and to the `forbidden`/`gone`/`unknown` outcomes (G2, G3, A2, B6).** Mechanical, response-neutral, closes the largest block of silent failures.
3. **Capture layer (optional part B of the roadmap slice), after steps 1 and 2.** Place `captureException` inside the helper and in a middleware around `next()`; an outer `withSentry` alone would see nothing because Astro catches exceptions itself (`routing/handler.js:59-108`). Cloudflare Workers Issues needs Wrangler 4.134.0 or newer (installed 4.131.1). Measure CPU on a deployed build before relying on a tracker under the Free-plan 10 ms limit.
4. **Dashboard status, labels and Origin visibility (G5, G4, G6).** `503` on essential load failure, one label per read, `500.astro`, JSON `code` in 403/404 answers.
5. **Session handling (G11, G13).** One client per request; log refresh errors; log missing secrets once.
6. **Client reporting (G7)** once a log endpoint exists.
7. **Release identity and verification (G10, G16):** `version_metadata`, `--tag $GITHUB_SHA`, a version marker and an authenticated canary.
8. **The rest:** B1–B5, A1, A3, A4, G9, G12, G14, G15, B6, B7 in any order; B1 and B3 are small user-visible fixes.
